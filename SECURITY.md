# Security Policy

## Overview

This repository takes security issues seriously. We appreciate reports from security researchers and responsible users who identify vulnerabilities in a respectful and responsible manner.

If you believe you have found a security vulnerability in this project, please report it privately and do not disclose it publicly until we have had a reasonable opportunity to investigate and remediate the issue.

## Supported versions

This project is a pilot and may not guarantee support for every release indefinitely. The maintainers determine which versions are actively supported based on deployment status, maintenance windows, and release history.

At a minimum:

- Only the latest supported release is expected to receive active remediation.
- Older or archived versions may receive limited support only at the maintainers' discretion.
- If you are reporting a vulnerability, please include the version, commit SHA, environment, and deployment details whenever possible.

## Reporting a vulnerability

Please use one of the following reporting paths, in order of preference:

1. GitHub private vulnerability reporting (preferred)
   - Use the repository's Security tab and select "Report a vulnerability" if that feature is enabled.
   - This keeps the report private while the issue is reviewed and triaged.

2. Approved private contact channel
   - If private reporting is not enabled, contact the project maintainer through an approved private communication channel.
   - If no public or private contact method is already documented, do not publish details publicly; instead, ask the repository owner or maintainers for a secure reporting route.

3. Email (template only)
   - If the maintainers have designated a security email address, send the report there.
   - Example placeholder: security@your-domain.example

## What to include in a report

Please include as much of the following as possible:

- Affected product name, repository path, version, or commit SHA
- Affected environment or deployment context
- A clear description of the issue and its impact
- Steps to reproduce the vulnerability
- Proof of concept or a minimal exploit example, if safe and appropriate
- Any suggested remediation or mitigation guidance

## Out-of-scope and safe testing guidance

We ask that reports be made in good faith and in line with responsible disclosure principles. Please:

- Do not exploit or access data beyond what is necessary to validate the issue
- Do not exfiltrate, alter, or delete data that does not belong to you
- Do not disclose the issue publicly until the maintainers have had a reasonable chance to review and remediate it
- Do not perform destructive testing or denial-of-service attacks against production systems
- Do not use social engineering, credential stuffing, or other abusive testing techniques

## Response expectations

We will do our best to acknowledge valid reports promptly, review them carefully, and work with the reporter to confirm the issue, coordinate remediation, and determine the appropriate disclosure timing.

There is no guaranteed response or resolution timeline for every report, but we will make a reasonable effort to communicate status updates during the investigation.

## Disclosure

Once a fix is available or a coordinated remediation plan is established, the maintainers may disclose the issue in a way that balances customer safety, project integrity, and responsible communication.

We appreciate responsible disclosure and will work with reporters to coordinate public communication when appropriate.

## Contact

For security-related questions or reports, please use the repository's private security reporting flow if available. If a private channel has been designated by the maintainers, use that channel instead. For any report that cannot be sent privately, please request a secure reporting method before disclosing details in public.
