# Security Policy

## Our approach

We’re a small team building this pilot and appreciate responsible reports that help us protect users and their data. Please report suspected vulnerabilities privately so we can investigate before details are shared publicly.

## Supported versions

We focus security fixes on the latest actively maintained version of the pilot. Older releases, forks, and deployments may not receive fixes. Please include the affected version or commit and deployment context in your report, if known.

## Report a vulnerability

**Preferred:** Use **Security → Report a vulnerability** in this repository, if private vulnerability reporting is enabled.

If that option isn’t available, contact the repository owner or maintainers through a private channel you already have. If you don’t have one, ask for a secure reporting route without posting technical details publicly. We have not published a dedicated security email address; please don’t send reports to guessed addresses.

Please include a concise description, affected component and version, impact, and steps to reproduce. A minimal proof of concept is helpful when safe to provide.

## Safe harbor and testing

Please make a good-faith effort to avoid harm while investigating. Don’t access, modify, or disclose other people’s data; disrupt services; or use social engineering, credential attacks, or destructive testing. Test only systems you own or have explicit permission to assess.

## What happens next

We’ll review the report, assess impact, and work with you on a fix and coordinated disclosure where appropriate. We’re a small team, so response and resolution times can vary; we can’t promise a specific timeline. Please keep the report confidential while we investigate and coordinate next steps with you.

We appreciate you helping us make the project safer.
